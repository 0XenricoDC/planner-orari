  <files>shift-planner.html</files>
  <action>
Aggiungi una funzione helper TOP-LEVEL (es. subito prima di `buildCoverageTable`, riga ~2231) che conta la copertura effettiva di un reparto in un giorno come presenza simultanea:

```
function repSlotCoverage(rId, dk) {
  const lsh = parseHour(lunchBreakStart);
  const leh = parseHour(lunchBreakEnd);
  let morning = 0, afternoon = 0;
  employees.forEach(emp => {
    const s = (schedule[emp.id] || {})[dk];
    if (!s || s.reparto !== rId) return;
    if (['riposo','malattia','ferie','permesso'].includes(s.type)) return;
    if (!s.start || !s.end) return;
    if (parseHour(s.start) < lsh) morning++;     // presente prima della pausa
    if (parseHour(s.end)   > leh) afternoon++;   // presente dopo la pausa
  });
  return Math.min(morning, afternoon);
}
```

Logica: un turno copre la mattina se inizia prima di `lunchBreakStart`; copre il pomeriggio se finisce dopo `lunchBreakEnd`. Una giornata intera conta in entrambi; mattina-only solo mattina; pomeriggio-only solo pomeriggio. La copertura garantita = `min` dei due slot.

Sostituisci con `repSlotCoverage(rep.id, dk)` TUTTI e quattro i punti che oggi contano headcount:
  - `buildCoverageTable`: il blocco `const working = employees.filter(...).length;` (riga ~2255-2258) -> `const working = repSlotCoverage(rep.id, dk);`
  - `updateStats`: il blocco `const working = employees.filter(...).length;` (riga ~2430-2433) -> `const working = repSlotCoverage(rep.id, dk);`
  - dentro `generateSchedule`, il loop `coverageIssues` (riga ~2005-2008): `const working = employees.filter(...).length;` -> `const working = repSlotCoverage(rep.id, dk);`
  - dentro `generateSchedule`, l'arrow locale `getRepWorking` (riga ~1917-1920): sostituisci il corpo con `const getRepWorking = (rId, dk) => repSlotCoverage(rId, dk);`

DECISIONE (motore + visualizzazione, documentata): il fix si applica SIA alla visualizzazione/validazione SIA al motore (getRepWorking usato da Pass 1/2 e dal loop coverageIssues). Motivo: se il motore continuasse a usare headcount mentre la tabella mostra la presenza simultanea, la tabella mostrerebbe gap che il motore considera coperti -> incoerenza che riapre il bug. Così il motore garantisce `minCopertura` come presenza simultanea. La guard di Pass 2 (`getRepWorking(fromRepId,dk) - 1 >= fromRep.minCopertura`) resta valida come euristica conservativa (rimuovere un full-day abbassa entrambi gli slot di 1). Nessuna nuova fase, nessun riposo/turno forzato: si cambia solo COME si conta, non quanti turni/riposi esistono.
